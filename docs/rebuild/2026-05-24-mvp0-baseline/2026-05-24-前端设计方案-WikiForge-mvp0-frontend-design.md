# 2026-05-24 WikiForge MVP0 前端设计方案 MVP0 Frontend Design

## 1. 设计目标

MVP0 前端是一个安静、稳定、中文优先的资料工作台。

目标：

- 让用户快速完成资料收纳、查看处理状态、触发 Wiki 整理。
- 只保留 MVP0 主流程入口。
- 沿用当前项目已有样式格式，避免后续页面反复调整。
- 不再做大 Dashboard、炫技控制台或高级能力入口。

## 2. 信息架构

MVP0 只保留五个一级入口：

| 入口 | 页面 | 主要用途 |
| --- | --- | --- |
| 收纳 | Capture | 路径扫描、浏览器上传、创建收纳任务 |
| 资料箱 | Source Inbox | 查看文件列表、重复文件、解析状态、失败原因 |
| Wiki | Wiki Workspace | 查看 Obsidian 写入结果、重跑 Wiki 整理 |
| 日志 | Run Log | 查看收纳、解析、Wiki 写入、index/log 更新记录 |
| 设置 | Settings | MVP0 运行口径、Raw Sources、Vault 托管目录、路径安全提示 |

默认首屏进入“收纳”。

不做：

- 首页 / Hero / 营销页。
- 总览大 Dashboard。
- 高级能力入口。
- MCP、向量、LifeOS、知识体检、Orchestration 控制台。

## 3. 页面职责

### 3.1 收纳

- 本地路径输入。
- 文件上传。
- 创建收纳任务。
- 展示最近一次任务状态。
- 不展示高级参数。

### 3.2 资料箱

- SourceFile 列表。
- 状态筛选。
- 文件详情抽屉。
- 展示来源、hash、类型、正文抽取状态、失败原因。
- 手动触发“整理到 Wiki”。

### 3.3 Wiki

- Wiki ingest 运行结果。
- Source page 路径。
- Wiki page 路径。
- index/log 更新状态。
- 写入状态和兜底原因。
- 支持单个文件重跑 Wiki 整理。

### 3.4 日志

- ImportJob 日志。
- 解析日志。
- Wiki ingest 日志。
- index/log 写入日志。
- 只做查询，不做复杂监控。

### 3.5 设置

- Raw Sources 根目录。
- Obsidian Vault 路径。
- 托管目录和写入边界。
- 扫描安全根提示。
- 当前不提供持久化设置表单。

## 4. 样式基线

MVP0 沿用当前项目已有样式格式，不沿用当前大控制台的信息架构。

### 4.1 样式来源

当前样式来源：

```text
frontend/src/styles/main.css
```

后续拆分时可整理为：

```text
frontend/src/styles/
  base.css
  layout.css
  components.css
```

拆分样式前，必须保持视觉格式一致。

### 4.2 固定格式

以下格式必须统一复用：

- 页面标题。
- 分区标题。
- 按钮尺寸和层级。
- 输入框和表单布局。
- 表格行高、列间距、分页。
- 状态标签。
- 抽屉和弹窗。
- 空状态、加载态、失败态。
- 页面内边距和区块间距。
- 圆角、边框、阴影尺度。

不允许每个页面自行发明一套按钮、表格、卡片或状态标签样式。

## 5. 布局规范

页面布局固定为：

```text
左侧导航 + 右侧工作区
```

要求：

- 左侧导航只展示五个一级入口。
- 右侧顶部展示当前页面标题和必要操作。
- 页面内容使用工作区分组，不做嵌套卡片。
- 详情使用抽屉，确认操作使用弹窗。
- 不做多栏监控台。

## 6. 中文优先

所有用户可见内容使用中文：

- 菜单。
- 按钮。
- 状态。
- 筛选项。
- 表格列名。
- 错误提示。
- 空状态和加载状态。

英文 code 不直接展示给用户。

错误提示必须说人话，例如：

```text
该路径与 Raw Sources 重叠，请选择其他目录。
```

## 7. 状态字典

状态码使用中文业务码值，由系统字典统一维护。代码层如需英文枚举名，只能作为内部实现细节，不能直接展示给用户。

字典表建议：

```text
system_dictionaries
  id
  dict_type
  dict_code
  label_zh
  description_zh
  sort_order
  color_token
  is_terminal
  is_success
  is_active
```

API 返回建议：

```json
{
  "statusCode": "已收纳",
  "statusLabel": "已收纳",
  "statusDescription": "文件已复制到 Raw Sources"
}
```

前端不得直接展示 `statusCode`。

## 9. 组件规则

### 9.1 按钮

- 主按钮：创建任务、上传、写入 Wiki。
- 次按钮：查看详情、刷新、重跑。
- 危险按钮：删除、清理、重置。MVP0 默认少用。
- 图标按钮必须有 tooltip。

### 9.2 表格

- 资料箱、Wiki、日志优先使用表格。
- 表格必须有空状态。
- 长路径默认省略，详情抽屉展示完整信息。
- 不展示宿主机敏感绝对路径，必要时展示相对路径或脱敏路径。

### 9.3 表单

- 标签使用中文。
- 必填项明确标识。
- 错误提示跟随字段展示。
- MVP0 不提供高级参数配置表单；可变运行配置优先通过环境变量和后续明确需求接入。

### 9.4 抽屉与弹窗

- 抽屉用于资料详情、Wiki 写入详情。
- 弹窗只用于确认操作。
- 不做抽屉套抽屉。

## 10. 验收规则

前端实现必须满足：

- 五入口导航固定。
- 首屏默认进入收纳。
- 用户可见状态为中文。
- 新状态先进入字典表，再进入 UI。
- 页面复用样式基线。
- 不出现高级能力入口。
- 前端构建通过。

验证命令：

```powershell
npm --prefix frontend run build
git diff --check
```
