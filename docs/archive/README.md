# WikiForge 文档归档说明

## 归档规则

所有历史文档按日期目录归档，同一天产生的归档文件放在同一个日期目录下。

目录格式：

```text
docs/archive/YYYY-MM-DD/
```

文件格式：

```text
YYYY-MM-DD-中文名-EnglishName-版本号.md
```

示例：

```text
docs/archive/2026-05-23/2026-05-23-需求文档-knowledge-base-prd-v0.2.md
```

### 同日滚动版本规则

同一天内，同一类文档如果多次更新，不再为每次更新复制一份新快照。优先更新当天该类文档的最新版本文件，并在文件内部追加版本记录。

版本号规则：

```text
v0.1 -> v0.2 -> ... -> v0.9 -> v1.0 -> v1.1
```

注意：

- 不使用 `v0.10` 这类版本号。
- 文件名版本号必须与文件内最新版本记录一致。
- 归档索引只指向最新版本文件，并说明该文件内包含多次更新。
- 已经存在的旧版本文件只作为历史保留，后续不要继续复制扩散。

### 长文件版本索引规则

如果同一个归档文件内版本记录过多，导致 AI 读取上下文过大，必须在文件顶部增加“版本索引 / Version Index”。

版本索引至少包含：

- 最新版本。
- 最新小节标题。
- 推荐阅读范围。
- 历史版本范围和读取条件。

AI 默认只读取版本索引和最新版本小节；只有需要追溯历史决策、需求演进或用户明确要求时，才读取旧版本内容。

主文档建议采用：

```text
中文名-EnglishName.md
```

带日期的过程文档建议采用：

```text
YYYY-MM-DD-中文名-EnglishName.md
```

如果同一天同一主题下有多份外部评审、调研或材料，可以在日期目录下创建主题子目录。主题子目录也采用中文名 + EnglishName：

```text
docs/archive/YYYY-MM-DD/中文名-EnglishName/
```

主题子目录内的文件仍然采用：

```text
YYYY-MM-DD-中文名-EnglishName-版本号.md
```

## 每个日期目录建议包含

- 当日 PRD 快照
- 当日技术架构快照
- 当日数据模型快照
- 当日实施计划或迭代计划
- 当日开发者日志
- 当日参考资料快照
- 当日归档索引
- 可选：主题子目录，例如 `架构评审-architecture-review`

## AI 开发前置规则

参与开发的 AI Agent 在进行代码开发、文档修改、方案设计或需求分析前，必须先查看最新日期快照：

1. 查找 `docs/archive/YYYY-MM-DD/` 中日期最新的目录。
2. 先阅读该目录下的 `YYYY-MM-DD-归档索引-archive-index-vX.Y.md`。
3. 再按任务需要阅读同目录中的需求文档、技术架构、数据模型、实施计划和开发者日志快照。
4. 最后再阅读 `docs/` 下的当前主文档。

如果最新快照、当前主文档和用户当前指令存在冲突，不要自行猜测，应先指出冲突并等待确认。

## 注意

- `docs/archive/` 根目录只放本说明文件。
- 具体归档文件不要直接放在 `docs/archive/` 根目录下。
- 主文档继续放在 `docs/` 下迭代。
- 当天最新归档文件可按滚动版本规则继续追加记录；已沉淀的旧版本文件作为历史快照，不再直接修改。
- `README.md` 保持通用入口命名，不强制改成中文 + 英文格式；归档快照可保留 `YYYY-MM-DD-README-vX.Y.md`。
